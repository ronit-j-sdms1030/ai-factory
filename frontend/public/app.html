Capability boundary

The skill file the intake agent is held to — what this platform can and cannot be asked to build, how it scopes a request that crosses the line, and the client's own vocabulary. Applies from the next conversation onward. This is the widest edit on this page: it changes what every future requirement is judged against, so each save is versioned and attributed.

Design system

The skill file every generated screen is written against — tokens, components and accessibility rules. Applies to the next generation and to any screen edited afterwards. Each save is versioned and the file is committed to Git beside the screens it governed.

Agent prompts

The tuning blocks inside each agent's instructions. Changing one affects every requirement generated afterwards; each save is versioned and the text used is committed to Git beside the artefact it produced. Instructions that hold a schema together stay in code and are not editable here.

What the agents have learned

Rules taken from corrections reviewers have already made. A rule is only applied once the same correction has been seen twice — one correction may be taste. Anything that changes what a screen does, or that contradicts a rule already in force, waits for approval here.
